Методи збору даних для ІАЗ ОУВ

Мета — не запам'ятати перелік технологій, а пройти повний цикл: сформулювати інформаційну потребу → отримати дані з мережевого джерела → оцінити джерело → привести дані до структури → сформувати формалізоване повідомлення → перевірити його перед завантаженням до ІАС. У підсумковому груповому кейсі весь цикл відпрацьовується на синтетичному обліку фактів обстрілів.

Навчальні дані є синтетичними. Вони демонструють методи роботи без використання реальних оперативних відомостей.

Правило заняття. Мережевий збір даних здійснюється лише з джерел, до яких є законний доступ, з урахуванням умов використання ресурсу, обмежень доступу, захисту персональних даних та вимог інформаційної безпеки.

1. Основи збору даних через мережу Internet

Практично мережевий збір можна представити як роботу з чотирма основними типами джерел.

Вебсторінки

HTML-сторінки офіційних ресурсів, новинних порталів, каталогів, публічних звітів.

API

Структурований автоматизований доступ, найчастіше JSON/XML, з фільтрами та параметрами запиту.

Відкриті файли

CSV, XLSX, JSON, XML, GeoJSON, PDF та інші набори, оприлюднені для завантаження.

Потоки / стрічки

RSS/Atom, журнали подій, телеметрія та інші джерела, що регулярно оновлюються.

4. Оцінка надійності мережевого джерела

Оцінюйте не «чи подобається ресурс», а сукупність ознак: первинність, ідентифікованість автора/установи, актуальність, можливість перевірки, узгодженість із незалежними джерелами.

Вправа 4 · Оцініть джерело0–100

Сценарій: вебсторінка містить статистичний звіт. Установа-власник чітко вказана; дата оновлення — сьогодні; є посилання на методологію та CSV; дані збігаються з другим незалежним офіційним ресурсом.

5. Збір даних з використанням формалізованих документів

Формалізований документ — це не просто «таблиця». Це узгоджена модель даних, у якій кожне поле має призначення, тип, правила заповнення та контроль.

Електронна форма

Найкраща для ручного введення: випадаючі списки, обов'язкові поля, автоматична дата, перевірка діапазонів.

report_id,report_time,unit,status,personnel_ready,vehicles_ready,comment\nRPT-001,2026-08-07T07:30:00+03:00,Unit-A,ready,92,14,No critical issues
{\n "report_id": "RPT-001",\n "report_time": "2026-08-07T07:30:00+03:00",\n "unit": "Unit-A",\n "status": "ready",\n "personnel_ready": 92,\n "vehicles_ready": 14\n}

Мінімальні правила формалізації

Один факт — одне поле

Не змішувати дату, місце й коментар в одному текстовому полі.

Коди й довідники

Для повторюваних категорій використовувати контрольовані значення.

Єдиний формат часу

Зберігати дату, час і часовий пояс однозначно.

Унікальний ID

Кожен документ і запис повинен мати стабільний ідентифікатор.

8. Груповий кейс: облік фактів обстрілів

Єдина практична ситуація для трьох груп. Аналітична група формує навчальний реєстр фактів обстрілів у вигаданому районі ALFA за період 06:00–08:00 07.08.2026. До обліку включаються лише події секторів B-2 та B-3.

Навчальні обмеження. Усі джерела, назви й події синтетичні. grid_x/grid_y — умовна локальна сітка 0–99, а не реальні географічні координати. Завдання відпрацьовує методи збору, валідації, provenance та інтеграції даних.

Підсумок заняття

Internet

Спочатку визначаємо інформаційну потребу, потім джерело й метод отримання. Завжди зберігаємо походження даних та параметри вибірки.

Формалізований документ

Цінність дає не формат файла, а контрольована структура: типи полів, довідники, обов'язковість, унікальні ID та автоматична валідація.

Головна теза: збір даних завершено не тоді, коли файл або відповідь API отримані, а тоді, коли дані перевірені, описані метаданими та приведені до форми, придатної для ІАЗ.
